## 8. First executable beta — candidate protocol

The following operational proposal is a new page-level contribution, distinct from the earlier quotations.

1. Freeze a set of low-risk tasks: keyword maintenance, source comparison, formatting and small code review. Include seeded anomalies and clean cases; retain originals.
2. Assign independent sessions to A–H plus a task-only baseline. Match model version, tools, context exposure, task budget and sampling settings where feasible. Randomize order and repeat. A–H are bundled conditions; later factorial comparisons can isolate individual ingredients.
3. Separate task completion from the curiosity log. Permit zero, one or many sparks. Logging does not authorize file changes, private-data disclosure or substitution of the task.
4. Preserve raw source pointers, observations, stated uncertainty, whether solicited, and eventual disposition. Use local access controls and explicit sharing permissions.
5. Assess task fidelity, provenance, reproducibility and material novelty using reviewers blinded to conditions where feasible. Preserve disagreement and evaluator limitations.
6. Retain unchanged control groups and complete histories. Introduce a new generation only with a documented delta and rationale; test transfer on unseen tasks.

| Candidate record field | Purpose |
|---|---|
| Run, model and condition ID | Reproducible comparison |
| Source pointer and inspected context | Separate exposure from unseen text |
| Assigned trajectory and authorization | C1 before C2 |

| Predicted or unexpected obstruction | Separate predeclared from post-hoc findings |
| Later evidence and counterexamples | Check correspondence |
| Disposition and reasons | Preserve, revisit, correct, discard, unresolved |
| Delta and dependent changes | Track longitudinal correction transfer |
